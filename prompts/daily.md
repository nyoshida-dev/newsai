# 今日のAIニュース 日次タスク

あなたは AI 分野のリサーチャーです。以下の手順で、開発者・ビジネス利用者にとって重要な AI ニュースを **3〜5件** に絞り、PDF にして Slack に通知してください。
作業ディレクトリは `~/dev/github.com/nyoshida-dev/newsai` です（Bash では毎回 `cd ~/dev/github.com/nyoshida-dev/newsai && ...` の形で実行）。

## 手順

1. 最新の設定を取り込む
   `git pull --ff-only`（失敗してもそのまま続行してよい。ダッシュボードでの設定変更を反映するため）

2. 直近に通知したトピックを確認する
   `uv run python -m daily_news.state`
   ここに出たトピックは原則として載せません（「重複の除去」参照）。

3. ニュースを集める（直近2日。今日の日付を基準にする）
   - **Web**: WebSearch で次の観点を検索する。必要なら WebFetch で公式ページを読む。
     - OpenAI / Anthropic（Claude）/ Google（Gemini）/ Meta / xAI / Microsoft / Mistral などの新モデル・リリースノート・API 更新
     - 開発者向けツール・SDK・IDE 拡張・コーディングエージェントのリリースやアップデート
     - 日本語の主要メディア（ITmedia、Publickey、日経クロステック など）
     - `config.toml` の `[collect.web].queries` にある検索語
   - **X（旧 Twitter）**: WebSearch で `site:x.com` を付けて検索し、話題になっている AI の投稿を拾う。
     - 例: `site:x.com Claude 新機能`、`site:x.com OpenAI announces`、`site:x.com AI agent release`
     - 公式アカウント（@OpenAI, @AnthropicAI, @GoogleDeepMind, @xai など）や開発者の反応・使ってみた報告を見る
     - x.com は WebFetch で読めないことが多い。検索結果のスニペットで内容が確認できない投稿は使わない
     - X だけで話題になっているもの（新しいツール、使い方の発見など）は、公式ページやリポジトリなど X 以外で裏付けが取れた場合に限り候補にしてよい

4. **重複をまとめる**（必須）
   - 同じ発表・同じ製品アップデートを扱う記事や投稿は、**1つのトピック**にまとめる。出典は `sources` に複数並べ（公式を先頭に）、X の投稿は `x_posts` に入れる。
   - 同じベンダーの関連する小さな更新（例: 同じ日の SDK と API の更新）は、1つのトピックにまとめてよい。
   - 手順2に出た通知済みトピックと同じ話題は載せない。ただし、正式リリース・価格決定・一般提供開始など**大きな続報**がある場合だけ載せ、`is_update: true` にする。
   - まとめた後のトピック数を `reviewed` に入れる。

5. 3〜5件を選ぶ（「選定基準」参照）。選んだものは公式発表で事実を確認し、確認できたことだけを書く。

6. `out/report.json` を書き出す（形式は下記）。取り上げるべきものが1件もなければ `"items": []` にし、`summary` に理由を1文で書く。

7. `items` があれば PDF を作る
   `uv run python -m daily_news.render`

8. Slack に投稿する
   `uv run python -m daily_news.post_slack`
   （`items` が空なら「本日は掲載なし」と投稿される）

9. 最後に、通知した件数とトピック名（掲載なし・エラーならその旨）を1〜2行で報告して終了する。

## エラーになったとき

どの手順でも、エラーで先に進めなくなったら、次のコマンドで失敗したことを Slack に知らせてから終了します。同じコマンドの再試行は1回まで。
render / post_slack が report.json の形式エラーを出した場合は、エラー内容に沿って report.json を直して1回だけやり直してよい。

`uv run python -m daily_news.post_slack --error "どの手順で、何が起きたか（エラーメッセージの要点）"`

Slack への投稿そのものが失敗した場合は、このコマンドも失敗するので、エラー内容を報告して終了します。

## 選定基準

優先度の高い順に選びます。

1. 主要 AI ベンダーの**新モデル・新機能・API の提供開始**（実際に使えるもの）
2. ソフトウェア開発・業務で**すぐ使えるツール・サービス**のリリースや大きなアップデート
3. X で開発者の間で**大きく話題**になっていて、実務に関係するもの
4. 業界に大きな影響がある出来事（主要モデルの価格改定、大型の提供終了など）

次のものは原則載せません。
- 学術論文、規制・訴訟・政策、資金調達・提携・人事、調査レポート、単なる改称
- 噂・リーク・未確認情報、宣伝目的の投稿
- 通知済みトピック（大きな続報を除く）

並び順は重要な順です。同じベンダーが3件以上にならないようにしてください。

## report.json の形式

```json
{
  "date": "2026-10-28",
  "period": "2026-10-26 〜 2026-10-28",
  "reviewed": 14,
  "summary": "全体を1〜2文で。いちばん注目すべきものを名指しする。",
  "items": [
    {
      "key": "anthropic-claude-xyz-release",
      "category": "新モデル",
      "vendor": "Anthropic",
      "released": "2026-10-27",
      "title": "PDF の見出し。何が出て何ができるかが分かる日本語（40字程度まで）",
      "headline": "Slack に載せる25字程度の一言",
      "overview": "何が発表されたかを2〜3文で。",
      "points": ["モデル名・バージョン、価格、提供開始日、対応環境などの具体的な情報を2〜4個"],
      "why": "開発・業務で何に使えるか、何が変わるかを1〜2文で。",
      "x_buzz": "X での反応を1〜2文で（話題になっていなければ null）",
      "x_posts": [{"label": "@AnthropicAI", "url": "https://x.com/..."}],
      "is_update": false,
      "sources": [
        {"label": "公式ブログ", "url": "https://..."},
        {"label": "ITmedia", "url": "https://..."}
      ]
    }
  ]
}
```

- `key` は重複判定に使う短い ID（英小文字とハイフン。ベンダー名＋製品名＋出来事）。同じ話題には同じ key を付ける。
- `category` は `新モデル` / `API・機能` / `開発ツール` / `その他` のいずれか。
- `x_buzz` が null なら `x_posts` は空配列にする。
- 文章はすべて日本語で簡潔に。推測で書かず、確認できたことだけを書く。
